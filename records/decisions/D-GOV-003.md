## Recommended sequence

1. **Choose one representative, reversible project task.** Start with coordinator, implementer and separate reviewer. Use specialist functions only when the task requires their output. Retain company titles as optional labels, not standing departments.
2. **Approve a bounded trial contract.** Use existing charter/task fields rather than new policy files. Name the environment, allowed data/actions, runtime grantor, read/write/tool scope, expiry, budget, rollback and escalation contact. A sandbox label alone proves no isolation. Use only harmless sentinel resources inside the authorized test boundary for denial tests.
3. **Measure the governance mechanism first.** Exercise normal completion, a deliberately failing check, interruption/handoff, and a prohibited action. Require actual denial evidence only where enforced isolation is claimed; in cooperative mode evaluate detection/escalation and disclose that writes are not technically prevented. Verify a fixed candidate independently and the resulting integrated state separately.
4. **Then compare value.** Prefer a single executor plus independent reviewer baseline versus coordinator/implementer/reviewer, with matched task criteria, tools, permitted context, review controls and total resource ceilings. A pure single-agent quality/cost benchmark is optional and cannot be treated as satisfying the independence requirement. Record defects, outcome quality, elapsed time, model/tool cost where available, coordinator effort and human interventions; include setup/context overhead. A single run is a usability probe, not evidence of general superiority.
5. **Refine only from findings.** Reduce duplicated onboarding if it causes confusion. Add persistent departments only after recurring work demonstrates the need. A maintenance drill follows when there is a concrete maintained system and separately bounded authorization; test ownership/substitution, fault response, rollback and in-flight policy migration.

Before execution, select run count, time and spend ceilings, retry limit, success thresholds, and stop rules. Stop at limits or on unauthorized mutation, data exposure, failed recovery, or unverifiable review. Stopping conditions are proposal-level requirements; no such trial has been authorized or run today.
