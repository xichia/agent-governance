## Acceptance and fixed interface

1. Isolated standard-library Python prototype and documented versioned contract. Expose `validate(payload, assignment, inputs) -> list[str]` without mutating inputs. Malformed/untrusted JSON-like values produce errors rather than crashes; this is an offline research validator, not a sandbox or production security boundary.
2. `assignment` is the coordinator-supplied trusted manifest, separate from the untrusted `payload`: assignment ID, expected writer session, expected attendance/title, dependencies with relative logical path/version/SHA256, and resource inventory. `inputs` maps logical dependency paths to actual bytes. Require exact dependency set and identifiers, hash actual bytes against manifest and receipts; substituted content must fail even if its receipt hash is recomputed. Hash matching cannot prove authorship, actual reading or authorization. Exact session string is only a label check.
3. Resource dimensions explicit: inventory units times seats per unit, never multiply total seats by quantity. Prototype trusted resource entries contain `inventory_units` and `seats_per_unit`; chair fixture uses one seat per chair. Candidate states use integer half-open `[start,end)` intervals, attendee count, seating mode `seated` or `standing`, and chair-resource ID for seated states. Reject missing/unknown required resource, oversubscribed simultaneous seats and simultaneous attendance above expected audience; allow adjacent intervals and explicit standing states. Do not claim complete attendee/staff/service readiness or solve X02 by this narrower checker.
4. Prose scope explicit: marketing copy comes from a deterministic renderer of trusted title/attendance, stored alongside structured fields, and must match exactly. Arbitrary paraphrases are unsupported rather than purportedly semantically validated. Reject the synthetic 180-versus-80 copy case. Evidence claims use statuses `supplied`, `verified`, `assumption`, `unresolved`: supplied requires known dependency path; verified requires a nonempty source URL; the latter checks presence, not truth/reachability. Assumptions/questions stay visibly labeled; no alleged semantic verification of free prose.
5. Independently authored adversarial cases exercise valid cases, stale/recomputed/wrong path/version/session/missing/duplicate receipts, capacity reduction and aggregation, valid standing/adjacency, contradictory copy, evidence status, malformed values (including booleans masquerading as integers). Runner asserts expected accept/reject and reports actual outcomes, including negative failures. At least 24 materially distinct cases; no implementation-mirroring claims of exhaustive coverage.
6. Separate Luna reviewer checks fixed candidate and tests, introduces at least one additional boundary/negative probe, reviews one-hour continuation prompt separately from prototype efficacy, and records findings/dispositions. Coordinator runs accepted tests and verifies historical artifact preservation before closure. Unavailable tools or exhausted repairs produce partial/blocked status, never a pass.

## Minimal schema agreed before parallel work

Assignment: `{assignment_id, writer_session, title, attendance, dependencies:[{path, version, sha256}], resources:{resource_id:{inventory_units,seats_per_unit}}}`.
Payload: `{handoff:{assignment_id,writer_session,status,dependencies:[{path,version,sha256}]}, attendance, title, states:[{id,start,end,attendees,seating,chair_resource}], marketing:{attendance,title,copy}, claims:[{id,status,text,source}]}`. For standing `chair_resource` must be null; for seated it is a known resource ID. Empty states are invalid; claims may be empty. Status must be `ready_for_review` for acceptance. Dependency list may be empty only when assignment's list is empty. Versions positive integers; hashes lowercase 64 hex characters; logical paths nonempty relative POSIX paths without traversal/absolute/backslash/URL components. Expose `render_copy(title,attendance)` returning exactly `f"{title} welcomes {attendance} adults."`. Fixture shape `{id,expect_valid,assignment,inputs:{path:text},payload}`. Unknown fields may be ignored; document that this is not an exact-key schema. Inputs may contain extra paths but assigned dependencies must be present and match.
