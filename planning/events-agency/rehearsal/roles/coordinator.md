# Coordinator contract — rehearsal only

Specialist contracts: [finance](finance.md), [risk](risk.md), [creative](creative.md), [marketing](marketing.md); separate [reviewer](reviewer.md).

- **Assigned agent / session / model:** coordinator assigns these at the start of a future run and records stable IDs. For this pack's drafting only, the coordinator is `/root`, model GPT-6; that identity is not a rehearsal assignment.
- **Accountable to / substitute:** the task owner; no substitute is configured. Escalate reserved decisions and unresolved priorities to the owner.
- **Policy / objective:** charter 0.1.1 at the task-pinned commit. Produce one coherent, source-traceable proposal for fictional event `EV-SCI-001` within brief v1, then apply only disclosed change `CH-001` and integrate a v2 proposal.
- **Inputs / outputs:** read the task, governance, brief, interface, source cards and change card. Assign the four specialists distinct run-scoped paths: `runs/<run-id>/outputs/finance.json`, `risk.json`, `creative.json`, and `marketing.json`. Own the sole integrated candidate at `runs/<run-id>/candidate/integrated.json`; maintain the change log alongside it. Deliver exact source IDs, versions and handoff metadata.
- **Dependencies:** finance and creative start from the same frozen brief/source pack. Risk receives their matching-version outputs before finalizing; marketing receives finance, risk and creative outputs. Coordinator verifies all four handoffs, matching versions, dependency receipts and CH-001 acknowledgements before integration. A blocked/stale output blocks dependent work.
- **Local decisions:** assign work, keep output ownership disjoint, sequence dependencies, reconcile evidence-supported details, and integrate within the brief and interface. Do not edit a specialist artifact on its owner's behalf; return a specific change request. Record competing options and evidence.
- **Reserved / escalation:** only the human owner can change mission, success criteria, source mode, risk appetite, permissions or the fictional budget/attendance/date/access ceilings. Never authorize real spending, contact, collection of attendee data, bookings, commitments, publication or operations.
- **Read / write / tools:** shared governance and relevant rehearsal inputs read-only; write only coordinator assignment/change records, the integrated candidate and `runs/<run-id>/metrics.md`. No network, external services, or real-world contact. Shared repository path conventions coordinate work but do not enforce ACLs.
- **Proposed run ceilings:** one run, maximum 60 minutes wall-clock including setup, work, change propagation, review, corrections and final reporting; six role sessions total (coordinator, four specialists, reviewer), no replacement/retry sessions; 8 minutes / 6,000 generated tokens and six model-response turns per specialist; 10 minutes / 8,000 tokens and ten turns for coordinator; 8 minutes / 6,000 tokens and four turns for reviewer; at most two correction rounds total. These planning bounds require explicit owner acceptance, are not platform-enforced grants, and do not authorize spending. If token telemetry is unavailable, use session, turn and wall-clock bounds and record tokens as unavailable. Stop at any bound.
- **Review / activation:** submit a frozen candidate ID (commit or content hash) and criteria to a distinct reviewer session. Do not choose the reviewer who drafted or integrated it. Resolve findings within the correction limit and obtain a scoped re-review of changed content. No self-certification; no live run or activation is authorized by this contract.
