## Exactly one proposed next experiment

**Recoverable context and revalidation fixture study** (preserved T01/T02/T03, synthesis X04). Test whether a declared context/retrieval protocol can recover missing facts, reject superseded memory and preserve unknown status when a capability is absent. This is an offline mechanism/protocol test first; an actual agent comparison would be a later separately scoped trial.

Use a fictional trusted source bundle: brief v1 with80 available chairs; authoritative amendment v2 with40; saved summary incorrectly retaining80; one additional required fact omitted from the initial packet; tool-capability record toggling retrieval available/unavailable. Assign immutable case IDs and source versions/content identities. These are new X04 fixtures, **not** modifications/imports of blocked X01 or real venue facts.

Compare three declared input conditions on the same objective and ground truth:

| Condition | Inputs | Observable expected behavior |
|---|---|---|
| A — full authoritative bundle | Both versions, current-version indicator, required fact and capability status | Report40 as current, identify80 as superseded, cite actual source and acknowledge capability state. |
| B — selective packet plus recovery pointers | Saved summary and index linking to current source and missing fact; capability status | With retrieval available, recover the current value/fact before affected decision. Without it, explicitly leave them unresolved. |
| C — selective packet without recovery pointers | Same summary/omissions, no recoverable index; capability status | Treat the unsupported current value/fact as unresolved rather than promote the old note to verified evidence. This is a diagnostic ablation, not a viable rollout recommendation. |

Predeclare grading: separate source-version correctness, necessary-fact recovery, false promotion of stale/unknown information, claim-status calibration and ownership compliance. A missing value safely marked unresolved is different from completing the factual objective; report both completeness and calibration. Record exact inputs, outputs/events and available timing/usage with unknowns explicit. An offline scripted fixture success establishes only protocol mechanics, not model compliance, general reliability, latency advantage or token savings. An independently reviewed task contract is required before implementation; availability failures produce a reproducible unrun protocol.

**Falsification:** if B accepts stale80 as current, invents the omitted fact or claims a failed lookup was verified, the proposed recovery/revalidation protocol fails on that case. If required current information is inaccessible, no success on factual recovery is claimed. A/C provide matched controls for what was supplied/recoverable; do not assign identical factual-success expectations to different information access. Subsequent actual model trials must disclose those information differences and cannot infer a context-efficiency win from the fixture design alone.
